# Domain docs

Use a single-context layout:

- `CONTEXT.md` at the repo root holds domain terms.
- `docs/adr/` holds architecture decisions.

## Before exploring

Read `CONTEXT.md` and any ADRs relevant to the task.
If these files do not exist, continue silently.
Create them through the domain-modeling skill when terms or decisions are resolved.

## Use domain terms

Use the terms defined in `CONTEXT.md`.
If a needed term is missing, reconsider the wording or note the gap for domain-modeling.

## Explain conflicts

If a proposal conflicts with an ADR, name the ADR and explain why the decision should be reviewed.
